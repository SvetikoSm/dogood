# ЗАДАЧА: цена 4900 + максимально простая форма заказа на сайте

Владелец просит ровно две вещи и **ничего сверх этого**:

1. Цена на сайте — **4900 ₽** (сейчас 3999 ₽).
2. Форма заказа сокращается до трёх вещей: **1–2 фото питомца, кличка (на том языке, на котором её напечатают на футболке), email**.

**Главное требование владельца:** загрузка фото и их последующая выгрузка в Google Drive и в таблицу **не должны сломаться**. Это самая хрупкая часть системы — относись к ней как к неприкосновенной.

Второе требование: сохранить исходный вид сайта, чтобы можно было быстро откатиться.

## Правила

- Делать ТОЛЬКО то, что описано ниже. Ничего попутно не «улучшать», не рефакторить, не переименовывать, не переверстывать.
- Не менять бэкенд и интеграции. Перечисленные ниже файлы трогать запрещено.
- `npx tsc --noEmit` и `npm run build` должны проходить.
- Не коммитить чужие незакоммиченные правки: на момент постановки задачи в рабочем дереве есть изменения в `lib/studio/pipeline/*` и `lib/studio/telegram/review-bot.ts` — они к этой задаче не относятся, оставить как есть.

## Шаг 0 (ОБЯЗАТЕЛЬНО ПЕРВЫМ) — точка отката

Владелец должна иметь возможность вернуть старый сайт быстро и без разбирательств.

1. Пометить текущее состояние тегом:
   ```bash
   git tag site-before-simplification
   git push origin site-before-simplification
   ```
2. Скопировать оригиналы двух файлов, которые будут меняться, в `docs/backup/`:
   - `components/landing/order-form.tsx` → `docs/backup/order-form.before-simplification.tsx`
   - `lib/landing-data.ts` → `docs/backup/landing-data.before-simplification.ts`

   Это буквальные копии «как было», чтобы можно было глазами сравнить или вернуть один файл, не откатывая весь репозиторий. Расширения оставить как есть, но добавить в самое начало каждого файла строку-комментарий: `// BACKUP COPY — not compiled, see docs/SITE-ROLLBACK.md`.

   **Проверить, что копии не попадают в сборку.** Если Next.js/TypeScript пытается их компилировать (файлы в `docs/` обычно не входят в `tsconfig` include, но это надо проверить сборкой) — переименовать в `.txt` вместо правки конфигов.

3. Создать `docs/SITE-ROLLBACK.md` — короткая инструкция на русском для владельца (не для разработчика):
   - как откатить всё одной командой (`git revert` нужного коммита + `bash scripts/deploy-production.sh` на сервере);
   - как вернуть только форму (скопировать файл из `docs/backup/` обратно);
   - что именно менялось (цена и состав полей формы), одним абзацем.

## Шаг 1 — цена 4900 ₽

Цена задана в двух файлах, оба менять:

**`lib/landing-data.ts`** — три записи товаров:
- `priceRub: 3999` → `priceRub: 4900` (3 вхождения, строки ~24, ~42, ~60);
- текст в списках преимуществ: `"3 999 ₽ — фиксированная цена футболки."` и `"3 999 ₽ за футболку."` → `4 900 ₽` (3 вхождения, строки ~35, ~53, ~71). Формат с неразрывным пробелом сохранить как в оригинале.

**`components/landing/order-form.tsx`**, строка ~146:
```ts
const SHIRT_PRICE_RUB = 3999;   →   const SHIRT_PRICE_RUB = 4900;
```

После правки прогнать поиск по проекту: `3999` и `3 999` не должны встречаться в `lib/` и `components/`.

## Шаг 2 — упрощение формы

**Файл только один: `components/landing/order-form.tsx`.**

### Что остаётся в форме

| Поле | Имя в FormData | Примечание |
|---|---|---|
| Фото питомца, 1–2 шт | `items[0][photos]` | механику НЕ трогать (см. ниже) |
| Кличка | `items[0][dogName]` | подпись поменять на: «Кличка — на том языке, на котором хотите видеть её на футболке» |
| Email | `email` | как есть |
| Согласие на обработку ПДн | `consentPersonalData` | оставить, это требование 152-ФЗ |
| Согласие с офертой | `consentTerms` | оставить |

### Что убрать из интерфейса

Приют (`shelterId`), ФИО (`lastName`, `firstName`, `patronymic`), телефон (`phone`), промокод (`promoCode`), способ доставки (`deliveryMethod`), адрес (`address`), калькулятор доставки, комментарий (`comment`), стиль принта (`printStyle`), пол (`gender`), размер (`size`), цвет футболки (`color`), цвет принта (`printColor`), переключатель «как предыдущая» (`sameAsPrevious` / `mirrorPhotosFrom`), кнопку «добавить ещё футболку».

### КАК убирать — критично

Бэкенд читает поля через `first(stringFields.get("..."))` и подставляет `""`, если поля нет. **Серверной валидации обязательных полей в `/api/order` нет** (проверено). Поэтому:

- **Достаточно убрать поля из разметки.** Никаких изменений в бэкенде не требуется и не допускается.
- Обязательно снять атрибут `required` с убираемых полей — иначе браузер заблокирует отправку невидимой формы.
- **Внутреннюю механику нескольких позиций (`lines`, `linePhotos`, `createLine()`) НЕ выпиливать.** Просто не показывать кнопку добавления, чтобы позиция всегда оставалась одна (`items[0]`). Удаление этой машинерии затронет код загрузки фото — а это ровно то, что ломать нельзя. Оставить как есть, скрыть только UI.
- Убрать со страницы неиспользуемый код (расчёт доставки, состояния `deliveryQuote`, `deliveryCalcState` и т.п.) можно только если это не затрагивает обработчик отправки. Если сомневаешься — оставь, лишний неиспользуемый код безопаснее сломанной отправки. Линтер может ругаться на неиспользуемые переменные — это допустимо.

### Лимит фото

`components/landing/order-form.tsx`, строка ~37:
```ts
const MAX_PHOTOS_PER_LINE = 8;   →   const MAX_PHOTOS_PER_LINE = 2;
```
Минимум — 1 фото (как сейчас, отправка без фото не должна проходить).

## Шаг 3 — на сайте остаётся только стиль «Life is better»

Два других дизайна («Я — скорость», «No rainy days») убираются с витрины. Выбор стиля в форме уже убран на Шаге 2.

### Что менять

**`lib/landing-data.ts`:**
- в массиве `catalogDesignTemplates` оставить только объект с `id: "life"`, объекты `id: "speed"` и `id: "rainy"` удалить (строки ~39–75);
- в массиве `printStyles` оставить только `{ value: "life", label: "«Life is better»" }`, две другие строки удалить.

**`components/blocks/catalog-feature.tsx`:** дизайн теперь один, и полоса вкладок сверху становится бессмысленной (одна одинокая кнопка выглядит как недоделка). Скрыть `Tabs.List`, оставив содержимое вкладки. Сам компонент не переписывать и на другую структуру не переводить — только спрятать переключатель.

**`components/landing/order-form.tsx`** — важная деталь: после удаления выбора стиля из интерфейса поле всё равно должно уходить на сервер со значением `life`. Добавить скрытое поле:
```tsx
<input type="hidden" name={`items[${i}][printStyle]`} value="life" />
```
Иначе колонка «Стиль» в таблице придёт пустой, а она нужна студийному конвейеру.

### Что НЕ трогать в этом шаге (иначе сломается)

1. **Тип `StyleSlug` в `lib/ops/style-masters.ts` оставить как есть:** `"speed" | "life" | "rainy"`. Он используется в студийном конвейере как ключ словарей (`STYLE_MASTER_FILE_LABEL`, а также `N8N_TEXT_STYLE_REF_FILE_IDS` и `MOCKUP_MASTER_FILENAMES` в `lib/studio/config.ts`). Сузишь тип — посыплется код студии, который к сайту отношения не имеет.
2. **Не удалять картинки из `public/`:** папки `public/products/speed/`, `public/products/rainy/`, `public/order-form-styles/speed/`, `public/order-form-styles/rainy/` должны остаться на месте. Скрипт `scripts/verify-site-images.sh` (выполняется на каждом деплое как шаг 8) проверяет доступность картинок всех трёх стилей — удалишь файлы, и **деплой упадёт**.
3. `lib/catalog-images.ts`, `lib/order-form-style-previews.ts`, `components/landing/catalog.tsx` менять не нужно — они просто перебирают массивы и подхватят сокращённый список сами.
4. Шаблоны и папки Drive для speed/rainy в студии не трогать.

## НЕ ТРОГАТЬ (ни строки)

Это работающий конвейер «фото → Drive → таблица», его поведение должно остаться идентичным:

- `lib/save-order-submission.ts` — разбирает `items[N][photos]`, конвертирует HEIC, готовит payload;
- `lib/forward-order-to-google.ts` — отправка в Apps Script;
- `lib/upload-order-photos-to-drive.ts`;
- `lib/convert-heic-server.ts`;
- `app/api/order/route.ts`;
- `scripts/google-apps-script-order-webapp.gs` и сама Google-таблица — колонки остаются те же, просто часть из них теперь придёт пустой (Приют, Телефон, Адрес, Доставка, Стиль, Цвета, Пол/размер). Это ожидаемо и нормально.

Внутри `order-form.tsx` **не трогать** механику фото:
- ключ `items[${i}][photos]` при `formData.append`;
- id инпута `photo-pick-${lines[i].id}` — на нём держится запасной путь для iOS, когда состояние React не успело обновиться;
- функции сжатия (`compressOne`) и связанные с ними состояния;
- порядок действий в `handleSubmit`: сжатие → `new FormData(form)` → `formData.delete` → `formData.append`.

## Приёмка

1. `npx tsc --noEmit` — чисто. `npm run build` — проходит.
2. Визуально: на странице товара и в форме цена **4900 ₽**, старых 3999 нигде нет.
3. Форма содержит ровно: загрузку фото (не больше 2), поле клички, поле email, два согласия, кнопку отправки.
4. На витрине только «Life is better», переключателя стилей нет, страница не выглядит поломанной (нет пустой полосы вкладок, нет дыр в вёрстке).
5. **Главная проверка — живая отправка заказа.** Запустить сайт локально (`npm run dev`), заполнить форму, приложить **2 настоящих фото** (желательно одно с iPhone в формате HEIC) и отправить. Затем убедиться:
   - в Google-таблице появилась новая строка;
   - в ней заполнены: `Кличка`, `Email`, `Папка с фото`, `Кол-во файлов` = 2, `Стиль` = `life`;
   - по ссылке из колонки «Папка с фото» на Google Диске лежат оба файла и они открываются.

   Если в окружении нет доступа к Google (нет `GOOGLE_*` переменных) — **не выдумывать обходных проверок и не считать задачу выполненной**, а прямо написать владельцу: «проверку выгрузки в Drive/таблицу выполнить не смог, нужен ваш живой тест».
6. Проверить отправку с телефона (или в мобильном режиме браузера) — форма должна отправляться, фото прикрепляться.
7. Прогнать `bash scripts/verify-site-images.sh` против локальной сборки (или убедиться, что папки картинок для speed/rainy остались на месте) — деплой проверяет их и упадёт, если файлы удалены.

## Известные последствия (упомянуть владельцу в отчёте, не «чинить»)

- Данные для доставки (ФИО, телефон, адрес, размер, цвет) больше не собираются на сайте — их придётся запрашивать у клиента отдельно после заявки.
- Дизайны «Я — скорость» и «No rainy days» пропадают с витрины, но их картинки, шаблоны и настройки студии остаются в проекте. Вернуть их = добавить обратно два объекта в `catalogDesignTemplates` и две строки в `printStyles`.
- На сервере цена ярмарочного бота задана отдельно (`FAIR_TSHIRT_PRICE_RUB=4999`) и этой задачей не меняется. Если нужна единая цена — это отдельное решение владельца.
